**① 静态表（9 行，`lib/family-labels.js:31-76`）** —— 中文短名与短网关名都在这里：

**② 取值链（`lib/family-labels.js:113-120`）** —— 表压过宿主标题：

```js

  const byId = BY_ID[id];
```

**③ 宿主 locale title（只解释了 `文件读写工具`/`文件搜索工具` 两行）** —— `@deepseek-ai/dsh-tool-fs/locale/zh.json` 就是 `{"meta":{"title":"文件读写工具"}}`。也就是说，即便把「表压过标题」修掉，`fs` 仍会显示中文——因为**这次要的是一律不翻译，宿主标题也得让位**。

### 1.3 判定：这三处该保留哪一层

| 层 | 现有值举例 | 保留？ | 理由 |
|---|---|---|---|
| 静态表 label | `搜索` / `记忆` / `MCP 管理` | **删除** | 它是「翻译过的名字」，不是原始名。且它压过一切，导致同一个包在不同插件里改名时这里永远不跟 |
| 静态表 gateway | `search` / `hindsight` / `mcp` / `session` / `image` / `video` / `blender` | **删除** | 短名把 `session_query` 和别人的 `session` 撞在一个命名空间里，也让 roster 与页面对不上 |
| 宿主 locale title | `文件读写工具` / `文件搜索工具` | **不使用** | 同样是翻译；且第三方插件普遍没有 locale，混用两种语言更难看 |
| 包名派生 | `Free Search` / `Image Gen` / `Hindsight Coding Agents` | **只保留这一层** | 唯一「原始名」，且**零配置、零维护**：新装插件立刻有名字 |

数据来源已核对：`lib/plugin-meta.js:228-234` 本来就会丢弃「title 等于包名」的标题，所以第三方包现在只能落到表里；表删掉后它们自然落到包名派生，不会突然显示成 `@perrylink/dsh-github`。

### 1.4 修法 A：把 label 变成纯派生函数

**A1. `lib/family-labels.js` 整表删除，改成一个纯函数。**

```js
// lib/family-labels.js —— 新形态（示意）
const PREFIXES = ["dsh-tool-", "dsh-plugin-", "dsh-", "plugin-"];
/** 缩写词：原样大写，否则 `fs` 会变成 `Fs`。 */
const ACRONYMS = new Set(["fs", "mcp", "api", "cli", "ui", "http", "url", "json", "ide"]);

/** `@vectorize-io/hindsight-coding-agents` -> `Hindsight Coding Agents` */
export function rawLabelOf(pkg) {
  let name = String(pkg ?? "");
  const slash = name.lastIndexOf("/");
  if (slash >= 0) name = name.slice(slash + 1);
  for (const prefix of PREFIXES) {
    if (name.startsWith(prefix) && name.length > prefix.length) { name = name.slice(prefix.length); break; }
  }
  const words = name.split(/[-_.\s]+/).filter((word) => word !== "");
  if (words.length === 0) return String(pkg ?? "");
  return words
    .map((word) => (ACRONYMS.has(word.toLowerCase()) ? word.toUpperCase() : word.charAt(0).toUpperCase() + word.slice(1)))
    .join(" ");
}
```

**A2. `familyLabelHints` 退回「只做兜底」**：删掉 `BY_PACKAGE`/`BY_ID` 查找与 `gateway` 返回，label 由 `rawLabelOf(pkg)` 给出，没有 pkg 时用 `rawLabelOf(id)`。

这条对唯一一个「没有包」的家族有可见影响：`BY_ID` 里的 `mcp_servers` 现在显示 `MCP 服务器`，删表后变成 `MCP Servers`（`rawLabelOf("mcp_servers")`）。它在本机当前没有注册 MCP 服务器，所以不在现场 13 行里；一旦接了 MCP 服务器就会以此名出现，网关名本来就是 `mcp_servers`（`BY_ID` 没有 `gateway` 字段），不变。

**A3. 网关名：删掉 `hints.gateway` 后无需改代码。** `lib/families.js:75-78` 的 `gatewayName(prefix, familyId, explicit)` 在 `explicit === undefined` 时返回 `` `${prefix}${familyId}` ``，现场 `gatewayPrefix: ""`，于是网关名自动等于 family id。

**A4. 已存在的用户配置不受影响。** profile `cordis.patch.yml:297-347` 的 `families:` 键是 **family id**（`blender_plugin` / `hindsight_coding_agents` / `mcp_connector` …），不是网关名；现场实测 14 条覆盖键与 family id 完全一致。改网关名不会让任何一条配置失配。想保留 `GitHub` 这种品牌大小写的人，可以用既有的 `families.github.label: GitHub` 覆盖（`lib/discovery.js:268` 已支持）。

**A5. 连带的面板与提示词**：`lib/bridge.js:171` 的 `gateway`、`lib/index.js:111` 的 roster、`lib/client.js:294` 的行内文案都读同一个函数，无需改动，自动跟随。

```js
  const sentence = endings.length > 0 ? flat.slice(0, Math.min(...endings)).trim() : flat;  // ← 第一刀：只留第一句
  const points = [...sentence];
```

### 2.3 修法 B：把 `summarize` 变成 `flatten`

```js
// 新语义：只做「压平空白」，不找句末、不截断、不加省略号
export function summarize(text) {
  return String(text ?? "").replace(/\s+/g, " ").trim();
}
```

配套三处小改：
1. `lib/plugin-meta.js:103` 的 `cap` 读取删除；`createMetaReader` 的 `options.cap` 一并删除（无调用方传它）。
2. `lib/plugin-meta.js:238` 改为 `text: summarize(text)`。
3. `lib/plugin-meta.js:34` 的注释（`/** Longest description this module will hand on, in code points. */`）删除。

**要不要留一个可选上限？** 建议留一个**默认关闭**的配置项 `maxDescriptionChars`（`0` = 不限制，默认 `0`），理由：`blender_plugin` 的 1251 B 占 12 个网关描述总量的三分之一，将来若再加两三个「大描述」插件，光描述就会重新吃掉 6 KB。留开关只花一行 config，不给默认行为加任何截断。

### 2.4 风险（必须明说）

- **每轮 +2468 B**（12 个网关）。按 `lib/bridge.js:78` 的 `tokensOf`（字节/3.2）约 **+770 tok/轮**，全部落在工具定义的 system 段——也就是**每轮都付、且吃前缀缓存**的那部分。
- 描述里可能混进换行、`|` 表格、markdown 链接。压平空白能解决换行；`blender_plugin` 的原文里就有 `（v3.0.4，GUI 优先，无头备用）` 这类括注，读起来没问题，但它是给「人」写的句子，不是给模型的操作说明——**这正是 0.7.0 曾用「只取第一句」换来的东西**。取消截短等于把这块判断权交回给插件作者。
- 与 `staticNotice: true` 无关：notice 只说「网关怎么用」，不会重复家族描述。

### 2.5 验收

- `summarize("第一句。第二句。") === "第一句。第二句。"`（不再丢第二句）
- `summarize("a\n\nb\tc") === "a b c"`（压平仍在）
- `summarize("word ".repeat(60))` 长度 > 120 且**不以 `…` 结尾**
- 现场：`blender_plugin` 网关描述含 `（v3.0.4，GUI 优先，无头备用）` 之后的内容；`tavily` 描述长度 527 B 量级；12 个网关描述合计 ≈3880 B。

## 3. 问题 C：启用插件后家族列表不自动更新

### 3.1 你复现的路径（原话）

> 「目前只有在启用渐进式披露插件的情况下重新停用后启用 tavily 插件才会被加载到家族列表，而且重新停用、启用渐进式披露插件之后，必须再重复这样一遍流程，tavily 插件才会被加载到家族列表」

这个「要两轮、且第二轮还得重来一次」的形状，正是**两个独立缓存各挡一层**的指纹：第一次停/启 tavily 打掉一层，第二次停/启 gate 打掉另一层。逐层拆开就是 §3.3。

```
          let plan = cache.get(root);  只在进程内首次构建      ← ④ 永不失效
```

**结论先说**：家族来源本身就是「自动检测所有包」——`lib/tool-scan.js:5-27` 的文件头注释写明「The mapping is therefore derived from what is installed, not from a list in this repository」，`lib/owner.js:9-32` 的 L1/L2/L3 三层归属也是同一个用意（L3 就是「扫 profile 里装了什么」）。**它不是白名单**。坏掉的不是设计，是**这条链上的三个缓存没有失效点**。

### 3.3 三层成因（全部有实验或代码依据）

**① 扫描计划缓存：进程内只建一次（`lib/tool-scan.js:67`）**

```js
/** Per-profile cache: the bundle list and file list change only on install. */
const cache = new Map();
```

注释写的是「change only on install」——但安装/启用**不会**让这个 Map 失效：`forgetScanCache()`（`:230`）只有测试在调。

实测（`_probe_scan_cache.mjs`，合成 profile）：先只有 `pkg-a` → 扫得 `{alpha_tool: 'pkg-a'}`；把 `pkg-b` 写进 `package.json` 的 `dsh.profile.bundles` 并落盘 → **同进程再扫仍只有 `pkg-a`**；`forgetScanCache()` 后第三次才看到 `beta_tool → pkg-b`。

**② `registered()` 的 revision 记忆化（`lib/owner.js:372-419`）**

`revision` 只在四处 +1：「wrapper 捕获到一次注册」（`:225`）、「`live.delete`」（`:231`）、「挂载时记录的 preexisting 名字」（`:281`）、「扫描学到新东西」（`:414`）。也就是说：**一个新包如果它的工具在 tool-gate 挂载之前就注册完了，并且磁盘扫描给不出答案，那么 `registered()` 的答案会永远停在旧值**。

现场细节：profile `cordis.patch.yml` 里 `dsh-tool-gate` 在 ~299 行、`dsh-tavily` 在 ~349 行——tavily **在 gate 之后**加载，它的注册理论上会被 wrapper 捕获（`_probe_wrap3.mjs` 证实：赋值后读回的函数 `name === "patched"`，即 patched 版本**确实生效**，只是 `===` 比较永远 false，这也是 `lib/owner.js:242-250` 注释里已经写明的坑）。所以 @ 的真正断点在①：**只要扫描计划是旧的，未被 wrapper 捕获的名字就永远归不上户**，而 `unknownOwnerPolicy: "expose"`（现场值）让它们留在 wire 上但不属于任何家族——页面自然没有 tavily 这一行。

**③ 刷新按钮不重扫（`lib/client.js:520-524`）**

```js
onClick: () => setReloadKey((key) => key + 1),   // 只改依赖，触发 useEffect 再 GET 一次
```

`useEffect`（`:185-202`）只是重新 GET `/describe`。**GET 不会清任何缓存**，所以按钮在「新装插件」这件事上是空操作——这与你的观察完全吻合。

**④ 冻结面（不是本次要改的，但要知道它存在）**

`lib/state.js:84-91` 的 `adopt()` 一旦跑过，`state.frozen` 就是本会话的最终工具集；`live.freeze` 现场是 `true`。所以即使①②③全修好，**当前会话的 wire 也不会变**——页面会立刻正确，模型要等下个会话。这一点在 §3.6 明说，不做「自动解冻」。

### 3.4 为什么「停/启一次只前进一格」

| 你的操作 | 打掉了哪一层 | 结果 |
|---|---|---|
| 停用 tavily | —— | tavily 的工具从 wire 消失，页面上本来就看不到它 |
| 启用 tavily | 若这次注册被 wrapper 捕获 → `revision += 1` | `registered()` 重算，但 `scanForOwners` 的 **plan 仍是旧的**；只有当工具名被 wrapper 捕获时才不需要扫描 |
| 停/启 tool-gate | 插件重挂载 → `initialOwners` 重新算一次 | 若此时 plan 仍是旧的、且 tavily 的工具又是在挂载**之前**注册的 → 还是看不到 |
| 再来一遍 | 这次 tavily 的注册发生在 gate 已挂着的时候 → wrapper 捕获 → `live` 有值 | 家族出现；但要等**新会话**才上 wire（冻结面） |

这条链每一格都对应上面四层里的一层，所以「必须重复一次」不是玄学。

### 3.5 修法 C（三步，互相独立）

**C1. 让扫描计划按 profile manifest 失效（`lib/tool-scan.js`）**

```js
// 现状
let plan = cache.get(root);
if (plan === undefined) { ...build...; cache.set(root, plan); }

// 改为：计划带指纹，指纹变了就重建
let plan = cache.get(root);
if (plan === undefined || plan.stamp !== manifestStamp(root)) {
  plan = { stamp: manifestStamp(root), packages: buildPlan(root) };
  cache.set(root, plan);
}
```

`manifestStamp` 读 `package.json` 的 `mtimeMs + size`（实测 **0.2 ms**，见 §7.3）。计划重建成本实测 **161.7 ms / 24 个 bundle / 1286 个源文件**——不便宜，所以只在 manifest 真的变了时才重建，而不是每次 `registered()` 都重建。

`forgetScanCache()` 保留，语义变为「无条件丢弃」。

**C2. 给 ownerIndex 一个 `forget()`（`lib/owner.js`）**

```js
// 加在 return { ownerOf, registered, … } 这个对象里（lib/owner.js:347 起）
forget() {
  scanned.clear();
  cached = undefined;
  revision += 1;      // 让所有按 revision 记忆化的下游一起失效
}
```

注意 `live` **不清**：它是实时归属，仍然可信；`preexisting` 也不清（那是「挂载前就在全局层的名字」，清掉会让 `ownerOf` 把它们当成不存在）。`revision` 的四个既有自增点（`:225` wrapper 捕获、`:231` `live.delete`、`:281` 挂载时的 preexisting、`:414` 扫描学到新东西）都不受影响。

`dispose()`（`:743` 处被调）里不必加 `forget()`：它已经拆了 wrapper。

**C3. 「刷新清单」变成真正的重扫（`lib/bridge.js` + `lib/client.js`）**

- 新增路由 `POST /api/dsh-tool-gate/refresh`：`isAllowed(req)` 之后执行 `forgetScanCache()` → `runtime.forgetOwners()` → `refreshFamilies({ force: true })` → 返回与 `/describe` 相同形状的快照（页面一次请求就能同时刷新列表与提示）。
- `refreshFamilies` 增加 `force` 参数：`force === true` 时**跳过签名比较**直接 `resolveNow()`；否则保持现状（签名比价是热路径，不能去掉）。
- 客户端按钮改为 `fetch("/api/dsh-tool-gate/refresh", { method: "POST", credentials: "same-origin" })`，成功后就地替换快照；失败保留旧快照并提示。
- **只允许 POST**：`isAllowed` 只校验 Host/Origin/loopback，不看 method（`lib/bridge.js:22-47`），所以写操作必须自己把住 method，并沿用现有 403 文案。

**C4（可选，不建议本期做）：家族来源改为 loader entries 全量播种。** 即在挂载/刷新时遍历 `ctx.loader.entries()`，对「声明了 `dsh.bundle` 且未 disabled 的包」各建一个家族，不等问题工具出现。它能让「装了没启用」的插件也出现在页面上，但会带来一批 0 成员的隐藏行（页面 `lib/bridge.js:167` `hidden: members.length === 0` 会隐藏它们），也让 `autoFamilies` 的语义变味。**本方案不采用**：现有「工具-driven + 全盘扫描」已经满足「不是白名单」，缺的只是失效点。

### 3.6 与冻结面的关系：必须提前说清

C1-C3 修好后：

| 场景 | 设置页 | 当前会话的 wire | 新会话 |
|---|---|---|---|
| 新装一个插件并启用 | **立刻出现**（点刷新清单或重新打开面板） | 不变 | 出现 |
| 停用一个插件 | 立刻消失 | 不变 | 消失 |
| 改家族 label / 描述 | 立刻变 | 不变（重挂载才重建网关） | 不变 |

也就是说，**这次修的是「看得见」，不是「立刻用得上」**。要「立刻用得上」，只能让本插件在检测到家族集合变化时把 `state.frozen` 置空——代价是**前缀重写**（这正是 `freeze` 默认 `true` 的初衷，见 `lib/client.js:630-637` 对 freeze 的说明）。你已经选了「冻结面完全不动，只影响新会话」，所以本文档不提供自动解冻，只在页面上加一句提示：**「新装的插件在新会话生效」**。

### 3.7 验收

- 单测 A：`scanForOwners` 在同一进程内，manifest 变化后**无需** `forgetScanCache()` 即可看到新 bundle（合成 profile，就是 `_probe_scan_cache.mjs` 的场景，断言从「必须 forget」翻转为「不必 forget」）。
- 单测 B：`ownerIndex.forget()` 之后 `registered()` 重新扫描，`snapshot()` 含新包。
- 单测 C：`refreshFamilies({ force: true })` 在签名不变时也调用 `resolveNow`（用一个计数桩验证）。
- e2e：`POST /refresh` 返回快照且 `families` 含新装包；`GET /refresh` 返回 405；跨站 Origin 返回 403。
- 现场：装一个可启停的插件（tavily）→ 启用 → 点「刷新清单」→ 页面立刻出现 `tavily` 行（不必重启任何插件）；再停用 → 立刻消失。

## 4. 不变量与风险

### 4.1 必须守住的不变量

1. **`families.<id>` 的键永远是 family id**，与网关名、label 无关；改 A 不让任何既有配置失配（现场 14 条覆盖键已核对）。
2. **同一条 wire 前缀内名字唯一**：删掉短网关名后，`gatewayPrefix` 撞名风险下降（`session` 与别的 `session` 不再冲突）。
3. **家族集合仍然只由「实际存在的工具」决定**（C4 不做），空家族不注册网关（`lib/index.js:528-543` 的 `emptyFamilyIds()` 保持）。
4. **描述文本仍只来自宿主/包元数据**，不在仓库里手写（`docs/改进方案-网关描述与提示词分层.md` 的结论不变）。
5. **`freeze` 语义不变**：本会话的 wire 只在下个会话变化。
6. **`/describe` 保持无副作用**；所有重扫只走 `POST /refresh`。

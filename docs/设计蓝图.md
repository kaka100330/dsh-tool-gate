## 0. 一句话

**让线上 `tools` 数组在一次会话里从头到尾逐字节不变**，把第三方工具家族收进常驻的"家族网关"工具，网关内部按名派发到注册表里仍然存在的真工具。工具集永不变化 ⇒ `startsSeries` 永不触发 ⇒ 前缀永不重写 ⇒ **额外缓存代价恒为 0**。

---

## 1. 目标与硬约束

### 1.1 目标

| # | 目标 | 度量 |
|---|---|---|
| G1 | 节省每请求固定工具 schema 成本 | 从 ~35,134 tok 降到 ≤14,000 tok（省 ≥60%） |
| G2 | 消除会话中途工具集变化导致的前缀重付 | change/series header 从 15 次/62 次降到 0 |
| G3 | 不破坏上下文压缩 | 压缩后网关仍可调用，激活状态不丢 |
| G4 | 不改变内置工具与 dsh-ops 的暴露逻辑 | `CORE`、`OPS` 两组工具原样保留在线上 |

### 1.2 硬约束（用户确认，不可动摇）

1. **零缓存代价**是最高优先级。任何会改动线上 `tools` 数组或系统提示词文本的做法一律否决，即使能换来更多节省。
2. **放弃"真激活"**。激活状态只存在于插件内存与 plugin record 中，**不进入 wire**。
3. **内置工具暴露逻辑不变**。`CORE`（45 个）与 `OPS`（7 个）原样暴露。
4. **dsh-ops 暴露逻辑不变**（`ops_*` 7 个工具不动，包括 `ops_discover_tools`）。
5. **不碰 PTC 模式**。仅在 native 呈现模式（标准模式 / 创造模式 / 极简模式）下生效；检测到 `ptc` 即自动停用本插件，不干预 wire。
6. **不允许模型嵌套调用工具**。网关不得派发到另一个网关；一次调用只派发一个目标工具。
7. **子代理完全独立**。每个 agent 一份冻结面与状态，互不可见、互不影响。

## 2. 调查结论：为什么"零缓存代价"只有一条路

这是整个方案的地基。以下每一环都已在实机代码中核对。

### 2.1 工具数组一变 ⇒ 前缀重写

```
dsh-agent-loop/lib/index.js:1059
startsSeries: startsRequestSeries
  || this.requestSurfaceGeneration !== this.session.surface.contentGeneration
  || preparedCall?.toolUpdate === void 0 && this.toolsChanged(assembly.tools)
```

`toolsChanged()`（`:929-936`）以 `session.requestHeader()` 为基线，用 `headerEquals` 逐字段比 JSON，工具按顺序比。只要名字集合或顺序变了就为真。

`startsSeries` 为真后，`step()` 进入 `SystemPromptProjection.project(rendered, { startsSeries: true })`（`:239-300`）→ 走 `!inHistory || startsSeries` 分支 → 用 `{op:"replace"}` 重写 surface 头部节点、清空其余 → **整段系统提示词（本机实测单请求前缀中位 ≈90K tok）重付**。

### 2.2 本机路由拿不到增量下发能力

当前路由（`C:\Users\Administrator\.dsh\profiles\desktop\cordis.patch.yml:9-42`）：

| 项 | 值 |
|---|---|
| 插件 | `@deepseek-ai/dsh-llm-pi-ai`，entry id `llm-pi-ai` |
| provider | `zhuanjie`（转接） |
| api | `openai-completions` |
| baseURL | `http://localhost:5642/api/v1` |
| 模型 | `proxy_auto`（contextWindow 1,000,000） |

`dsh-llm-pi-ai/lib/index.js:397-421` 的 `COMPLETIONS_COMPAT_GATE` 把两个关键开关标为 **`withhold`**：

```js
supportsMidConvoSystemMessages: "withhold",
supportsMidConvoToolAdditions:  "withhold",
```

`assertOfferedCompatFields()`（`:540-548`）会在**配置期**直接抛 `PiAiCatalogError`，所以**无法通过 cordis.patch.yml 打开它们**。`conversationUpdates(model)`（`:785-793`）因此返回 `{}`：

```js
if (compat === void 0 || !("supportsMidConvoSystemMessages" in compat) || !compat.supportsMidConvoSystemMessages) return {};
```

⇒ 本机 `toolUpdate === undefined` 且 `systemPromptUpdate === undefined`。

**这就是"尾巴注入激活信息"救不回来的原因**：尾巴追加（`developer/message` 或 `user/message`）确实不破坏前缀，但它只解决"通知"，没解决"工具数组本身变了"。而工具数组一变，头部就重写。两者是两个独立的前缀段。

### 2.3 `deferLoading` 在本机是死路

- `dsh-llm/lib/index.js:786-796`：`toolUpdate === undefined` 分支第一步就是 `withoutDeveloperMessages(messages)`（`:755-758`），并且**剥掉 `deferLoading` 后全量发送**。
- `dsh-llm-pi-ai/lib/index.js:1269-1271`：`toolsOf()` 是 `options.tools?.filter((tool) => !tool.deferLoading).map(piTool)` —— 标了 `deferLoading` 的工具被**直接从线上抹掉，没有任何补发机制**。
- `dsh-session/lib/index.js:337-347`：`tool-addition` 必须在 `headerSeq` 里恰好命中一个工具、带完整 definition、`deferLoading` 若存在必须为 `true`。

⇒ 用 `deferLoading` 会让工具**永久不可见**。**绝不能用。**

### 2.4 但"隐藏的工具仍可执行"——这条成立

| 环节 | 事实 | 证据 |
|---|---|---|
| 派发入口 | 走**注册表**，不看 `assembly.tools` | `dsh-tools/lib/index.js:3236` `const visible = this.get(name, agent);` |
| `assembly.tools` 用途 | 只用于 header 记录（`renderPrompt` 只读 sections，不读 tools） | `dsh-agent-loop/lib/index.js:1050-1075` |
| 会话校验 | `tool/call` 只记 `callSeq`，**不校验是否在 header tools 内** | `dsh-session/lib/index.js:833-837` |
| 未声明调用 | agent-loop / session / llm 三层均**无** `UNKNOWN_TOOL` 校验（已全量 grep） | — |
| PTC 折叠 | `collapses()` 只在 `modeFor(scope)==="ptc"` 时生效 | `dsh-tools/lib/index.js:3195-3197` |

⇒ **从 wire 上摘掉的工具，只要还在注册表里，就能执行。** 这是本方案成立的前提，已确认。

### 2.5 结论

**唯一路径 = 冻结线上面。**

让 wire `tools` 数组从会话第一个请求起就永不变化。既然不能"事后激活"，就必须"事前分组"：把冷门家族换成常驻网关。

### 3.4 与 billion-context（v0.1.212）的兼容

`C:\Users\Administrator\.dsh\profiles\desktop\node_modules\billion-context\dist\agent\dsh-native.js`（`name="bili-native"`，`inject=["tools","commands","agents"]`）：

## 4. 家族识别：静态扫描不可用，运行时可以

### 4.1 为什么静态扫描不行（两次实测）

**宽松扫描**（扫所有字符串字面量，看是否等于某个工具名）——归属 92/141，但**串包极其严重**：

| 工具 | 误判归属 | 真归属 |
|---|---|---|
| `write` | billion-context | `dsh-tool-fs` |
| `edit` | dsh-image-gen | `dsh-tool-fs` |
| `subagent` | hindsight-coding-agents | `dsh-tool-subagent` |
| `todo_write` | dsh-free-search | `dsh-tool-todo` |
| `skill` / `research` | 双包争抢 | `dsh-tool-skill` / `dsh-free-search` |

**严格扫描**（只认 `name:` 与 `defineTool(` / `defineContentToolFixture(` / `createMcpToolDefinition(` 的第一个参数）——零串包，但**只覆盖 83/141**：`video_locate`、`video_zoom`、`skill`、`research`、`workflow` 全漏，剩 58 个"未归属"里真内置与真第三方混杂。

⇒ 静态扫描**只能当构建期产物 + 兜底表**，不能作为运行时实现。

### 4.2 可行的运行时方案：包装注册入口，从调用方 ctx 反查包名

**原理链（全部已验证）：**

1. `ToolRuntime` 的 `register` 是**原型方法**（`dsh-tools/lib/index.js:2974`，类体定义）⇒ 可包装。
2. 服务实例通过 `createTraceable` 代理暴露；`getPropertyDescriptor` 沿原型链查找（`cordis/lib/index.js:75-82`）⇒ 包装原型会被命中。
3. `Service` 构造器装载 `symbols.tracker = { associate: name, property: "ctx" }`（`cordis/lib/index.js:1768-1783`），`createTraceable`（`:120-158`）让 `service.ctx` 在**被调用时解析为调用方 ctx**。
4. 于是 `register` 执行期间的调用方 ctx 就是**注册该工具的插件的 fiber ctx**。
5. 沿 `ctx.fiber` → `fiber.parent` 上溯，找到带 `fiber.entry` 的那层 → `fiber.entry.options.name` = **包名**。
   loader 正是这么关联的：`cordis-plugin-loader/lib/index.js:628-641`（`fiber.entry = fiber.parent[Entry.key]`），`Entry` 类在 `:310-317`，`Entry.key = Symbol.for("cordis.entry")`。

**得到：`toolName → 包名`，精确、无猜测、自动跟随插件变化。**

**实现要点：**

```js
import { symbols } from "@deepseek-ai/cordis";

const target = ctx.tools[symbols.original] ?? ctx.tools;   // 剥掉 traceable 代理
const proto  = Object.getPrototypeOf(target);              // ToolRuntime.prototype
const original = proto.register;

proto.register = function (definition) {
  const disposer = original.call(this, definition);
  // 还原调用方 ctx：镜像 getTraceable 的 shadow 语义
  let callerCtx = this;
  if (callerCtx?.[symbols.shadow]) callerCtx = Object.getPrototypeOf(callerCtx);
  const owner = packageOf(callerCtx);   // 沿 fiber.parent 找 fiber.entry.options.name
  if (owner) ownership.set(definition.name, owner);
  return disposer;
};
```

**包装时机问题**：loader 并行加载，本插件加载之前注册的工具捕获不到。所以必须有兜底层。

## 6. 方案设计

### 6.1 三条不变式

| # | 不变式 | 保证者 |
|---|---|---|
| **I1** | wire `tools` 数组逐字节恒定（含顺序） | 冻结面 F0（§6.2） |
| **I2** | 渲染后的 system prompt 文本逐字节恒定 | 注入的是**静态常量段**，不随任何状态变化 |
| **I3** | messages 前缀不变 | 本插件**不追加任何 message**（`developer/message`、`user/message` 一律不写） |

**I3 是硬禁令**：任何"告知模型家族清单"的信息都只能通过 ①网关工具自身的 description（静态）或 ②`action:"list"` 的**工具返回值**，绝不写进对话消息流。

### 6.2 冻结面 F0

```
F0 = { CORE ∪ OPS ∪ Context ∪ 网关工具 } 减去 alwaysHide    并上 alwaysExpose
```

- 每个 agent 在**首次** `system-prompt/assemble` 时计算一次，写入 plugin record `plugin:tool-gate/state`。
- 此后每次 assemble 都输出 F0 对应的 schema 列表，**顺序由 `orderTools` 的默认 name 排序决定**（现状未配置 `toolOrder`，故按 name 字典序，稳定）。
- **不在 F0 里的工具**：从 `assembly.tools` 中移除。它们仍在注册表里，可被网关派发。
- **F0 计算之后新注册的工具**：一律不上线（Q4=A）。延迟到下一次新会话生效。例外：本插件自己的网关工具。
- **`resume` / `fork`**：按 `pluginRecordOf` 从 session 恢复 F0，不重算。

**关键实现**：assemble waterfall 里做 `{...assembly, tools: frozenSchemas}`，其中 `frozenSchemas` 在首次算完即**缓存为不可变数组**，之后直接返回同一份引用 ⇒ 逐字节恒定（`structuredClone` 只在首次做一次）。

| `blender` | Blender | 15 |
| `mcp` | MCP-Mgmt | 25 |
| `mcp_servers` | MCP-Servers（动态 `mcp__*`） | 1（可增长） |
| `github` | GitHub | 14 |
| `image` | Image | 6 |
| `video` | Video | 6 |
| `search` | Search | 9 |
| `hindsight` | Hindsight | 8 |

> 0.8.0 已对齐这张表的设计意图（家族名 = 包名的直译）：网关名改为 `hindsight_coding_agents`、
> 标签为 `Hindsight Coding Agents`。`image`/`video`/`search`/`mcp` 同理改为

**结构恒定的 schema**（**不放 `enum`**，否则成员变化会改 schema）：

```json
{
  "type": "object",
  "properties": {
    "action":    { "type": "string", "enum": ["list", "call"], "description": "list = 查看本家族全部工具及其完整参数；call = 调用其中一个" },
    "tool":      { "type": "string", "description": "action=call 时必填：本家族内某个工具的精确名字" },
    "arguments": { "type": "object", "description": "action=call 时传给目标工具的参数对象，必须精确匹配该工具的参数定义" }
  },
  "required": ["action"],
  "additionalProperties": false
}
```

`description`（静态，长度恒定，**不写成员数量**）：

> `Blender 3D 建模与交付能力组（15 个工具）。先用 action="list" 取回本组全部工具名、用途与完整参数定义，再用 action="call" 指定 tool 与 arguments 调用其中一个。`

（每个家族的 description 首句不同，其余措辞完全一致，便于模型形成稳定心智。）

### 6.4 `action:"list"` 的语义（Q5=B）

**用户选择："list 家族后，暴露家族内所有工具"。**

这里的"暴露"发生在**工具返回值**里，不发生在 wire 上 —— 这是零缓存代价的前提。具体：

- `list` 返回该家族**全部成员**的完整定义：`name` + 完整 `description` + **完整 `parameters` JSON Schema**。
- 不截断、不分页。单个家族最大 25 个工具（MCP-Mgmt）≈4,338 tok，一次返回完全可接受。
- 返回为 `content: [{type:"text", text: <markdown>}]`，正文里参数用紧凑 JSON 代码块。
- **同一个家族在同一次会话里二次 `list`** 返回一句话提示"本次会话已列过，定义见上一条结果"（~30 tok），避免重复灌入。

### 6.5 常驻静态提示（Q7）

必须**逐字节恒定**。追加到 `system-prompt/assemble` 的一个 `section`（`name: "tool-gate"`，`order` 固定），文本常量：

```
部分扩展能力按家族分组提供：blender / mcp / mcp_servers / github / image / video / search / hindsight。
调用前先对该家族 action="list" 取回工具定义，再用 action="call" 指定 tool 与 arguments 执行。
```

> ⚠ 这段文本里的家族清单是**常量**，不随实际家族变化。若某家族当前无成员，网关仍常驻并返回"本家族暂无工具"。这是为了字节恒定——**不要**把它做成动态拼接。

约 30 tok。

### 6.6 网关派发实现

```js
async execute(args, exec) {
  if (args.action === "list") return renderFamilyListing(family, members, listedBefore);

  // action === "call"
  assert(!isGateway(args.tool), "不允许嵌套调用：目标工具不能是家族网关");
  assert(members.has(args.tool), `${args.tool} 不在 ${family} 家族内；先用 action="list" 查看`);

  const subCallId = `${exec.callId}:gw:${++seq}`;   // 前缀用于误调拦截器识别
  const result = await ctx.tools.execute({
    callId: subCallId,
    rootCallId: exec.rootCallId,
    name: args.tool,
    arguments: args.arguments ?? {},
    ...(exec.agent ? { agent: exec.agent } : {}),
    signal: exec.signal,
  });

  // 子调用不会自动落 session 的 tool/call（只有 agent-loop 与 PTC 各自 append），
  // 所以由本插件记一条 plugin record 供审计/回放。
  appendPluginRecord(exec.agent.session, "plugin:tool-gate/dispatch", {
    family, tool: args.tool, callId: subCallId,
    isError: result.isError === true,
  });

  return result;   // ToolExecutionResult 原样透传
}
```

**要点说明：**

1. **不传 `parent`**。`collapses()` 只在 `modeFor(scope)==="ptc"` 时生效（`:3195-3197`），native 模式下不需要，且 4.1 已定"不碰 PTC"。本插件在 ptc 模式直接停用。
2. **`isConcurrencySafe: () => false`**。串行派发，避免与调度器并发池纠缠。
3. **子调用走完整策略链**：`execute → prepareExecution`（`tools/pre-execute` waterfall → guards → dispatch → post → finalize），所以目标工具自己的权限、`guard`、`projectContent`/`finalizeContent` 全部照常生效 —— 这是选公开 `execute` 而非直接调 definition 的原因。
4. **返回值原样透传**。`ToolExecutionResult` 已是"lossless frozen snapshot"，网关不重组、不摘要，避免二次开销与信息损失。
5. **`arguments` 必须 lossless JSON 可序列化**（`createExecution` 会 `snapshotJsonValue`，失败抛 `TypeError`）。网关 `arguments` 字段类型是 object，需先校验并给出友好错误。

### 6.7 误调拦截（Q8 之前的 T5=B）

模型可能从历史里见过某个被隐藏的工具名，直接调用它。**拦截并提示**：

```js
ctx.on("tools/pre-execute", (exec, next) => {
  if (isGatewayDispatch(exec.callId)) return next();          // 网关自身派发放行
  if (!belongsToGateFamily(exec.name)) return next();          // 非家族工具放行
  if (frozenExposure.has(exec.name)) return next();            // 已暴露的放行
  return {
    kind: "deny",
    reason: `${exec.name} 属于 ${family} 家族，未直接暴露。请调用 ${family} 网关：`
          + `先 action="list" 查看定义，再 action="call" 指定 tool="${exec.name}"。`,
  };
}, { global: true });
```

- **必须放行网关自身的派发**：用 `callId` 前缀 `:gw:` 识别（`isGatewayDispatch`）。这是最稳的判据——因为子调用的 `callId` 完全由我们构造。
- 若不想 deny，可放宽为 `{ kind: "ask" }`（走审批），但默认 deny + 明确指引更省轮次。
- `deny` 的结果是 `Error: <reason>` 的 `isError: true` 结果，模型能读到完整指引。

### 6.8 冻结后新工具的处置（Q4=A）

| 场景 | 行为 |
|---|---|
| 第三方插件热重载注册了新工具 | 不上线。log 一条 `toolgate: deferred <name> (owner=<pkg>)`，下次新会话生效 |
| MCP 连上新 server，新增 `mcp__*` | 不上线。但若用户主动 `action:"list"` `mcp_servers` 家族，**能看到并调用**（因为它在注册表里，网关按名派发即可） |
| 工具被注销（插件卸载） | 从注册表消失 ⇒ 网关派发时 `get()` 返回 undefined ⇒ `UNKNOWN_TOOL`。网关预先检查并返回友好错误 |
| 本插件自己的网关工具 | 例外，始终在 F0 里 |

**这条要写进 README**：升级第三方插件后如需新工具立即生效，请开新会话。

### 6.9 子代理隔离（T7=C）

- 状态以 `agent` 为键（`WeakMap<Agent, AgentState>`），在 `agent/created` 建立、`agent/disposed` 回收。
- `assemble` 的 `context.scope === agent`（`assembleContextFor`），据此取该 agent 的状态。
- 子代理**独立计算**自己的 F0 与家族集合，不继承父级。
- `tools/pre-execute` 拦截器按 `exec.agent` 取状态，不跨 agent。

### 6.10 时序

```
[进程启动]
  └─ apply(ctx, config)
       ├─ 解析配置、加载 L2 静态归属表
       ├─ 包装 ToolRuntime.prototype.register（L1 归属采集）
       ├─ 计算家族定义（package→family 映射）
       ├─ 注册 N 个网关工具（global 或 preset scope）
       ├─ 注入静态 section「tool-gate」
       ├─ 注册 tools/pre-execute 拦截器
       └─ ctx.on("agent/created", ...) 建立 per-agent 状态

[新会话首个 assemble]
  ├─ 扫 ctx.tools.schemas(agent) 得全部工具
  ├─ 三层归属判定 → name→family 映射
  ├─ 计算 F0 = (CORE ∪ OPS ∪ Context ∪ 网关) − alwaysHide ∪ alwaysExpose
  ├─ structuredClone 出 frozenSchemas（不可变快照）
  ├─ appendPluginRecord(session, "plugin:tool-gate/state", { v, frozenAt, exposure, families })
  └─ 返回 { ...assembly, tools: frozenSchemas }

[后续每个 assemble]
  └─ 直接返回缓存的 frozenSchemas（同一引用，逐字节恒定）

[resume / fork]
  ├─ 遍历 session events → pluginRecordOf → 命中 plugin:tool-gate/state
  └─ 恢复 F0 与家族映射，不重算

[模型调用网关]
  ├─ action="list" → 返回家族成员完整定义（同一会话只完整一次）
  └─ action="call" → ctx.tools.execute(目标工具) → 原样返回结果
```

## 7. 数据结构

### 7.1 内存

```ts
interface AgentState {
  agent: Agent;
  ready: Promise<void>;
  families: Map<string, FamilySpec>;        // 家族名 → { label, description, members:Set<string> }
  toolFamily: Map<string, string>;          // 工具名 → 家族名（仅家族成员）
  exposure: readonly ToolSchema[] | null;   // F0 的 schema 快照（首次算完即冻结）
  exposureNames: ReadonlySet<string>;
  origin: Map<string, "L1" | "L2" | "L3">;  // 归属判定来源，供自检
  listed: Set<string>;                      // 已 list 过的家族
  restored: boolean;                        // 是否从 plugin record 恢复
}
```

### 7.2 持久化（plugin record）

```ts
appendPluginRecord(session, "plugin:tool-gate/state", {
  v: 1,
  frozenAt: "2026-11-06T00:12:00.000Z",
  exposure: ["ask_user_question", "blender", "github", ...],   // 只存名字
  families: { blender: ["blender_rt_cmd", ...], github: [...] },
  gateVersion: "0.1.0",
});
```

**只存名字，不存 schema** —— resume 时用当前注册表里的 definition 重建（若某工具已不存在，跳过并 warn）。这样插件升级后 schema 自动最新，同时暴露集合（决定前缀的那部分）保持稳定。

### 7.4 插件卸载

- 包装的 `proto.register` 必须在 effect 里恢复原函数（用 `ctx.effect` 收集 dispose）。
- 所有 `appendPluginRecord` 的类型点 `plugin:tool-gate/*`。
- 卸载后 assemble 回到无冻结状态 ⇒ 工具集变化 ⇒ 一次前缀重付。**这是预期行为**（`--off` 降级用）。

## 9. 风险与退路

| # | 风险 | 影响 | 应对 |
|---|---|---|---|
| **R1** | 网关内 `ctx.tools.execute()` 重入。已核实 `createExecution` 无重入锁，`prepareExecution` 会跑 `tools/pre-execute` waterfall | 拦截器自环 | 用 `callId` 前缀 `:gw:` 识别放行。已验证可行 |
| **R2** | `tools/pre-execute` 按 `scopeTarget` 派发，子代理是否继承 | 拦截遗漏 | 拦截器 `{ global: true }`；状态按 `exec.agent` 取 |
| **R3** | 包装 `proto.register` 是全局副作用，可能与其他插件冲突 | 归属错乱 | 只读采集、不改变原行为；dispose 时还原；自检日志可发现 |
| **R4** | `orderTools` 若将来配置了 `toolOrder`，未知工具名会抛错 | 启动失败 | F0 只含已存在工具；网关工具名加入白名单；文档标注"改 toolOrder 需同步" |
| **R5** | 冻结导致新工具延迟生效，用户以为插件坏了 | 体验 | 网关 `action:"list"` 对注册表里实际存在的工具**全部列出**（不限于 F0）⇒ 冻结的工具仍能发现和调用，只是不在 wire 上 |
| **R6** | 某第三方插件把工具名注册成与家族名冲突（如叫 `blender`） | 注册冲突 | `gatewayPrefix` 配置；启动时检测冲突并报错 |
| **R7** | billion-context 若将来接管 `tools` | 双方改同一段 | 当前 `LANE_OWNED_REQUEST_KEYS` 明确不含 tools；若上游变更，本插件仍胜出（在 assemble 层，先于 wire 层） |

## 10. 不做什么（明确排除）

- ❌ 不用 `deferLoading`（本机 = 永久不可见）

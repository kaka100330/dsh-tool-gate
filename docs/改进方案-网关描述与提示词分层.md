# dsh-tool-gate 改进方案：网关描述与提示词分层（v0.6）

> 目标版本：0.6.0 → 0.7.0
> 依据：源码通读（`lib/` 20 个文件）+ 宿主 API 核对（`@deepseek-ai/dsh-app-boot` 0.2.1-rc.5、`@deepseek-ai/dsh-tools`、`@deepseek-ai/dsh-system-prompt`、`@deepseek-ai/dsh-plugin-package-inventory-deepseek`）+ 本机运行时实测（GUI `http://127.0.0.1:54488`，profile `desktop`，12 个可见家族、38 条 ungrouped）
> 本文档回应四个问题：① 网关名称/信息被硬编码在插件里；② 新增网关拿不到描述；③ 设置页「未参与折叠（只读）」显示内置插件；④ 每个网关重复一遍网关使用说明。
> 与既有文档的关系：`docs/改进方案.md`（v0.5，未跟踪）§2.1 的硬编码审计表把 D 项（`family-labels.js`）判为「低（可接受）」——**本文档显式推翻该结论**：D 项不是可接受的展示层冗余，它正是问题 ① 与问题 ② 的直接原因。其余 A/C/E/F/G 项结论不变。

## 1. 问题 ①②：网关描述的通用来源

### 1.1 现状与根因

网关 description 的生成只有一处，`lib/gateways.js:35-47`：

```js
function describeGateway(family) {
  const label = family.label || family.id;
  const detail = family.description || "";
  return [
    `${label} 家族的网关。${detail}`,
    "这个家族的成员工具不在本轮工具列表里，全部通过本网关访问：",
    "1) action=list → 返回成员工具的名字、说明与完整参数定义；",
    "2) action=call + tool + arguments → 调用指定成员，返回值与直接调用一致。",
    "同一会话内第二次 list 同一家族只回一句提示（定义已在历史里）。",
  ]
    .filter((line) => line !== "")
    .join("\n");
}
```

`label` 与 `detail` 都来自 `family`，而 `family` 由 `lib/discovery.js:102-120` 的 `makeFamily` 填充：

```js
function makeFamily(id, pkg, options) {
  const hints = familyLabelHints(id, pkg);   // ← family-labels.js
  return { id, label: hints.label, description: hints.description, ... };
}
```

`familyLabelHints`（`lib/family-labels.js:86-93`）读两张手写表：

```js
export function familyLabelHints(id, pkg) {
  const byPackage = pkg === undefined ? undefined : BY_PACKAGE[pkg];
  const byId = BY_ID[id];
  return {
    label: byPackage?.label ?? byId?.label ?? id,
    description: byPackage?.description ?? byId?.description ?? "",
    ...(byPackage?.gateway === undefined ? {} : { gateway: byPackage.gateway }),
  };
}
```

`BY_PACKAGE` 九条、`BY_ID` 一条，全是硬编码。用户报的两个症状都直接由此产生：

- **症状 ①**（信息硬编码且已过期）：`github` 家族读到的是手写的 `"GitHub repositories, issues, pull requests and reviews"`，而 `@perrylink/dsh-github` 的 `package.json` 里写的是 `"GitHub PRs, reviews, issues and CI for DeepSeek Harness: approval-gated write tools, a CI composite action, a polling review bot and a status-check gate."` —— **手写值已经和真实值脱节**。
- **症状 ②**（新增网关无描述）：`computer_use_win`、`tavily`、`fs` 三个家族在两张表里都没有条目，于是 `description` 落到 `""`，网关 description 只剩 `"computer_use_win 家族的网关。"`。实测 live `describe`：

```
| id                | label            | description |
| computer_use_win  | computer_use_win | ""          |
| fs                | fs               | ""          |
| tavily            | tavily           | ""          |
```

`lib/discovery.js:171-174` 其实已经预留了注入口，但从未被喂过数据：

```js
if (family.description === "" && typeof metadata === "function") {
  const meta = metadata(pkg);
  if (typeof meta?.description === "string") family.description = meta.description;
}
```

**断点在第 1.3 节：`metadata` 从 `resolveFamilies` 一路透传到 `deriveFamilies`，只有最上游的调用方没传。**

### 1.2 宿主已有的通用通道：`pluginPackages.metaOf()`

设置页「插件」页面显示的那段描述（用户引用的 `dsh-computer-use-win` 那 248 字符）不是硬编码，是 `@deepseek-ai/dsh-app-boot` 的 `PluginPackages` 服务读出来的。

服务定义（`.../dsh-app-boot/lib/index.js`，`class PluginPackages extends Service`，`super(ctx, "pluginPackages")`）：

| 成员 | 位置 | 作用 |
|---|---|---|
| `packageOf(specifier, parentURL)` | `:3544` | 解析包目录并读 `package.json`，返回 `{ name, version, dir, manifestPath, manifest }`。**不要求包导出 `./package.json`**。 |
| `metaOf(specifier, parentURL)` | `:3562` | = `readPluginMeta(specifier, parentURL)`（`:2216-2247`），返回 `{ title?, description?, icon?, error? }`。 |
| `refresh()` | `:3534` | 安装/卸载插件后由 `dsh-plugin-manager/lib/index.js:2341` 调用（`if (packages?.resolution !== void 0) await packages.refresh();`）。 |

`readPluginMeta` 的取值顺序（`:2216-2247`）：

1. `dictionariesOf()` 枚举 `<pkg>/locale/*.json`（语言 id 取文件名），每个文件读 **`parsed.meta.title` / `parsed.meta.description`**，必须是非空字符串，否则抛错。
2. 仅当 specifier 无子路径（`packageName === specifier`）时读 `<pkg>/package.json`，取 `manifest.name` / `manifest.description` 作为 fallback。
3. `localizedText()`（`:2188-2198`）：**没有任何语言条目时返回纯字符串；有语言条目时返回 `{ en, zh, … }` 映射**。
4. 任何异常都被吞成 `{ error: "Plugin metadata for <specifier>: ..." }`；三项全空时返回 `undefined`。

注册时机（`.../@deepseek-ai/dsh/lib/profile-boot-C14i-8IN.js:306`）：

```js
await hostCtx.plugin(PluginPackages, { resolution: composed.resolution });
```

**在 profile Loader entries 之前**，所以任何 profile 插件都能 `ctx.get("pluginPackages")`。

官方参考实现（宿主自带，`dsh-plugin-package-inventory-deepseek/lib/index.js:66-94`）——注意它**同时用两个解析锚点**：

```js

  ...
  const packageName = barePackageName(moduleName);

  if (packageName !== void 0) manifest = barePackageManifest(packageName, anchors, this.packages);

```

而 `dsh-host-plugin-inventory/lib/index.js:123-150`（设置页那份描述的生产者）用的是**每个 entry 自己的解析基址**：


### 1.4 实现方案

#### 1.4.1 新模块 `lib/plugin-meta.js`

职责：给定包名，返回一句话描述与一个短名，带三级兜底与缓存。**不硬编码任何插件。**

```js
/**
 * Plugin display metadata, read from the host instead of from a table in here.
 *
 * Three layers, in order:
 *  1. `pluginPackages.metaOf(specifier, baseUrl)` — the exact call the settings
 *     page's plugin list makes, so this plugin and that page can never disagree.
 *  2. `pluginPackages.packageOf(...).manifest.description` — covers plugins that
 *     ship no `locale/` and do not export `./package.json`
 *     (`dsh-video-storyboard` is exactly this case: layer 1 returns undefined).
 *  3. `family-labels.js` — a cosmetic fallback for first-party packages whose
 *     manifest describes the module rather than the plugin, and for the
 *     `mcp_servers` pseudo-family, which has no package at all.
 *
 * Every read is cached by manifest path + mtime, so a plugin upgrade is picked up
 * without a restart and a steady-state turn pays one `stat` per family at most.
 */
```

对外接口（只暴露两个函数）：

| 导出 | 签名 | 说明 |
|---|---|---|
| `createMetaReader(options)` | `options = { ctx, logger }` | 返回 `{ describe(pkg), title(pkg), dispose() }` |
| `describe(pkg)` | `(pkg: string) => { text: string, source: "metaOf" \| "manifest" \| "hint" \| "none" }` | `text` 已做截断（见 1.6） |
| `title(pkg)` | `(pkg: string) => string \| undefined` | 仅当宿主 title 不是包名本身时才返回（见 1.5） |

解析基址的确定：**优先用 Loader entry 自己的 `entry.parent.tree.ctx.baseUrl`，取不到时回退 `ctx.baseUrl`**，与宿主实现一致。

```js
const baseFor = (pkg) => {
  const tree = ctx.get("loader");
  for (const entry of tree?.entries?.() ?? []) {
    const name = entry?.options?.name;
    if (typeof name !== "string") continue;
    if (barePackageName(name) !== pkg) continue;
    const base = entry.parent?.tree?.ctx?.baseUrl;
    if (typeof base === "string") return base;
  }
  return typeof ctx.baseUrl === "string" ? ctx.baseUrl : undefined;
};
```

`barePackageName`（照抄宿主 `dsh-app-boot/lib/index.js:1276-1282` 的语义）：

```js
function barePackageName(specifier) {
  if (specifier.startsWith(".") || specifier.includes(":") || isAbsolute(specifier)) return undefined;
  const [first = "", second = ""] = specifier.split("/");
  return first.startsWith("@") ? `${first}/${second}` : first;
}
```

**软取宿主服务，不写进 `inject`。** 与 `dsh-host-plugin-inventory`（`static inject = ["loader"]`，`pluginPackages` 用 `ctx.get()`）保持同一姿态；`lib/index.js:53-57` 的注释已经说明为什么该插件的 `inject` 要尽量短——一个硬依赖缺失会让插件永久挂起。`pluginPackages` 取不到时三级兜底会自动退化到 `family-labels`，行为等价于现状。

#### 1.4.2 接线

`lib/index.js`：


`metadata` 在 `deriveFamilies` 里**只在 `family.description === ""` 时才被调用**（`lib/discovery.js:171`）——也就是说，用户显式配置的 `families.<id>.description` 覆盖优先级最高，硬编码兜底只在没有更好来源时生效。这个顺序是对的，保持不动。

#### 1.4.3 记录描述来源

给家族记录加一个只读字段，让设置页能回答「这句话是谁说的」：

```js
// lib/discovery.js makeFamily 之后
family.descriptionSource = describeSource;   // "override" | "metaOf" | "manifest" | "hint" | "none"
```

- `"override"`：来自 `families.<id>.description`（`applyFamilyOverrides`，`:263`）。
- 其余三个由 `metadata()` 的返回值携带（`{ description, source }`）。
- `lib/bridge.js:143` 的 `description: family.description ?? ""` 旁边加 `descriptionSource`，`lib/client.js:276-278` 的 hint 行末尾按来源加一个小字标注（`来源：插件`/`来源：兜底表`）。

这不是装饰：本方案上线后，用户能直接从页面看出某个网关是不是还在吃兜底表——这是问题 ② 不再复发的人工哨兵。

### 1.5 label / title / gateway 名的取值规则

实测 `metaOf().title`：**第三方几乎都返回包名本身**（`dsh-computer-use-win`、`@perrylink/dsh-github`、`@moguiyu/dsh-tavily`…），只有第一方给了真短名（`@deepseek-ai/dsh-tool-fs` → `{en:"tool-fs", zh:"文件读写工具"}`）。

所以 **title 不能直接当 label 用**（会把 `GitHub`、`搜索`、`图像` 这些短名替换成 `@perrylink/dsh-github`）。确定的优先级：

| 优先级 | 来源 | 例子 |
|---|---|---|
| 1 | 配置覆盖 `families.<id>.label` | 用户显式改名 |
| 2 | `family-labels.js` 的短名 | `github` → `GitHub`；`free_search` → `搜索` |
| 3 | `metaOf` title，**仅当它不是包名本身**（且是纯字符串或取到 `zh ?? en`） | `@deepseek-ai/dsh-tool-fs` → `文件读写工具` |
| 4 | `humanizeLabel(id)`（通用规则，非硬编码表） | `computer_use_win` → `Computer Use Win`；`tavily` → `Tavily` |

`humanizeLabel` 是纯函数：按 `_` 切分、每段首字母大写、保留 `mcp`/`fs`/`api` 等短词的既有大小写约定即可：

```js
const humanizeLabel = (id) => id.split("_").map((w) => w.charAt(0).toUpperCase() + w.slice(1)).join(" ");
```

实测效果：`computer_use_win` 与 `tavily` 两个原本「只有 id」的家族拿到可读名字，`fs` 拿到宿主的 `文件读写工具`。

**`gateway`（网关工具名）不受本方案影响**：它由 `familyIdOf`（`lib/discovery.js:68-83`）确定性派生，是 wire 表面的一部分，改名会让前缀抖动。`family-labels.js` 里 `gateway` 提示（`session_query` → `session`）仍只作短名用。

### 1.6 截断规则

插件 description 实测最长 1251 B（`dsh-blender-plugin`），直接塞进网关 description 会喧宾夺主。截断算法（已实测）：

```js
function summarize(text, cap = 120) {
  const t = String(text).replace(/\s+/g, " ").trim();
  if (t === "") return "";
  // 1) 优先取第一个「真句末」：CJK 句号/感叹/问号，或后面跟空格/行尾的英文句点
  //    （`\.(?=\s|$)` 是为了不把 `v3.0.4` 里的点当句末）
  const ends = [t.search(/[。！？]/), t.search(/\.(?=\s|$)/)].filter((i) => i >= 0).map((i) => i + 1);
  const sentence = ends.length > 0 ? t.slice(0, Math.min(...ends)).trim() : t;
  // 2) 首句仍超长时，按「码点」截到 cap 以内，并在最后一个词/标点边界收口
  const cps = [...sentence];
  if (cps.length <= cap) return sentence;
  const head = cps.slice(0, cap - 1).join("");
  const cut = Math.max(head.lastIndexOf(" "), head.lastIndexOf("，"), head.lastIndexOf("、"),
                       head.lastIndexOf("；"), head.lastIndexOf("："), head.lastIndexOf("——"));
  const body = cut > Math.floor(cap * 0.55) ? head.slice(0, cut) : head;
  return body.trimEnd().replace(/[，、；：—-]+$/, "") + "…";
}
```

两个要点：

- **按码点切，不能按 `String.length`**：`slice(0, 120)` 会把一个 CJK 字符切成半个代理对（`dsh-blender-plugin` 的描述里就有 emoji 与全角标点）。
- **`cap = 120` 是实测选出来的**：160 码点时 `dsh-blender-plugin` 会带上大段功能枚举，120 码点时 12 个家族合计 1648 B，而最短的 `computer_use_win`（原始 248 B）仍能保留到 `…bridged into DSH via @deepseek…`，语义完整。

各 cap 的合计体积（12 家族，含 `网关 · label：` 前缀）：

| cap | 合计字节 | ≈ tok |
|---|---|---|
| 160 | ~1900 | ~594 |
| **120** | **1648** | **515** |
| 100 | ~1450 | ~453 |
| 80 | ~1200 | ~375 |

### 1.7 边界情况

#### `mcp_servers` 家族（没有包）

`lib/discovery.js:180-196` 造这个家族时传的是 `familyLabelHints(id, undefined)`——没有 `pkg`，三级读取全部无从下手。通用做法：

`family-labels.js` 的 `BY_ID.mcp_servers`（`"Tools exposed by connected MCP servers"`）降级为兜底。

**可选增强（不在本期范围）**：MCP server 若有 `instructions`，`dsh-mcp-client` 会把它注册成 `mcp:<server>` 段落（`dsh-mcp-client/lib/index.js:736-743`）。这些段落经过本插件的 disclosure 通道时是可读的，可取首句作为描述。但它依赖 prompt 归属成功、且 instructions 常为空，**不作为主路径**。

#### 子路径 specifier

`metaOf` 对带子路径的 specifier **不读 `package.json`**（`readPluginMeta` 里的 `packageName === specifier` 判定）。实测：

| entry | `metaOf` 结果 |
|---|---|
| `dsh-ops/discovery` | ✅ `{en:"Enable dynamic tool loading", zh:"启用动态工具加载"}`（该包 exports 里逐个列了 `./<name>/locale/*.json`） |
| `@deepseek-ai/dsh-plugin-manager/tools` | ❌ undefined（无对应 locale 导出） |

因此读取时**先用 entry 自己的 specifier 试一次，失败再用 `barePackageName` 试一次**，两级都拿不到才降级。

#### 本插件自己的 `locale/` 结构是错的（顺带修）

宿主 `dictionariesOf()` 读的是 `parsed.meta.title`，而 `dsh-tool-gate/locale/*.json` 现在是**顶层**字段：

```json
// locale/en.json —— 现状，宿主读不到
{ "title": "Tool Gate", "description": "Collapse third-party tool families behind 8 stable gateway tools, …" }
```

`textOf(meta?.title)` 拿到 `undefined` → 抛 `must be a non-empty string` → 被 `readPluginMeta` 吞成 `{error}`。**实测 `readPluginMeta("dsh-tool-gate", profileBase)` 返回的是 `package.json` 的 description，locale 完全没生效。** 修法：

```json
{ "meta": { "title": "Tool Gate", "description": "Collapse third-party tool families behind 8 stable gateway tools, …" } }
```

`locale/zh.json` 同理。改完后本插件在设置页的标题会从包名变成 `工具网关`。

### 1.8 缓存与失效

| 关注点 | 设计 |
|---|---|
| 读一次还是每轮读 | **每个家族重建时读一次，之后缓存**。实测 12 次 `readPluginMeta` 冷启 68.5 ms（其中 51.88 ms 是首次模块解析，落在第一个包上），热态 0.5–3 ms/次。绝不能放进每轮 prompt 组装路径。 |
| 缓存键 | `manifestPath`（由 `packageOf` 给出）+ `mtimeMs`。`metaOf` 只给文本，所以先用 `packageOf` 定位清单，再 `metaOf` 取本地化文本。 |
| 失效 | 家族表在 `refreshFamilies()`（`lib/index.js:253`）里按签名重建，重建时顺带校验 `mtimeMs`；插件升级会改 mtime，于是描述自动跟上，不需要监听宿主事件。 |
| 清理 | `dispose()` 清空 Map；`ctx.effect` 里注册。 |
| 降级 | 任何一层抛错都返回 `{ text: "", source: "none" }`，绝不冒泡——设置页和 prompt 组装路径都不能因为一个坏插件清单而失败。 |

## 2. 问题 ④：网关使用说明抽离到系统提示词

### 2.1 现状是「两边都说了同一件事」

**网关工具 description 侧**（`lib/gateways.js:35-47`）：每个网关各带 4 行、**351 B** 的通用说明。

**系统提示词侧**（`lib/index.js:88-114` 的 `buildNotice`）：已经有同样的三条语义：

```
每个网关两个动作：`action: "list"` 返回该家族全部成员的名字、说明与完整参数定义；`action: "call"` 配 `tool` 与 `arguments` 调用成员，返回值与直接调用一致。
成员定义在第一次 `list` 之前不占上下文；`list` 过一次后不必重复调用。
直接调用已收起成员的名字会被拦截并提示改走网关——那不是工具本身的错误。
```

实测（12 家族）：这 4 行样板 **351 B × 12 = 4212 B**，占网关 description 全部体积 4964 B 的 **85%**。用户说的「一般场景下会有很多个网关，而这些网关使用方法都一样」——重复次数就是网关数。

### 2.2 目标分层

| 信息 | 归属 | 理由 |
|---|---|---|
| 「带 `action`/`tool`/`arguments` 的工具是网关」 | 系统提示词 | 与具体网关无关，一辈子说一次 |
| `list` / `call` 的语义、重复 `list` 的回答、直呼被拦截 | 系统提示词 | 同上 |
| **这个网关背后是哪个家族、能做什么** | 网关 description | 每个网关唯一不同的信息 |
| 参数含义 | 参数 schema 的 `description` | 与所在工具绑定，模型读 schema 就能看到 |

**分界线很简单：凡是每个网关都会说的，就不该出现在网关里。**

```js
function describeGateway(family) {
```

### 2.4 新的 notice 文案

`lib/index.js` 的 `buildNotice` 重写为「规则（一次）+ 名单（一行）」两段：

```
## 工具网关（渐进披露）

本轮工具列表里带 `action` / `tool` / `arguments` 三个参数的网关工具，各代表一个插件家族：家族的全部成员工具已从本轮工具列表移出，按需取用。

- `action: "list"`：返回该家族全部成员的名字、说明与完整参数定义；同一家族第二次 `list` 只回一行提示，定义已在历史里。
- `action: "call"` 配 `tool` 与 `arguments`：按成员定义调用，返回值与直接调用一致。

直接调用已收起成员的名字会被拦截并提示改走网关——那不是成员工具本身的问题。
```

加一行名单（让模型一眼看到本轮有哪些网关，而不用遍历工具列表反推）。三种写法实测：

| 写法 | 字节 | 例子 |
|---|---|---|
| 只列网关名 | **152** | `本轮收起：\`blender\`、\`computer_use_win\`、\`search\`、\`fs\`、\`github\`、\`hindsight\`、\`image\`、\`mcp\`…` |
| 网关名 + label | 280 | `本轮收起：\`blender\` Blender · \`computer_use_win\` Computer Use Win · \`search\` 搜索 · …` |
| label = 网关名 | 311 | `本轮收起的家族与网关：Blender = \`blender\`；Computer Use Win = \`computer_use_win\`；搜索 = \`search\`；…` |

**采用「网关名 + label」（280 B）**，理由是它同时成立：

- 网关名必须出现 —— 模型要靠它在工具列表里对上号，`lib/index.js:88-114` 的现状也是这么写的（`` - `blender` — Blender``）。
- label 必须出现 —— 它才是「这个网关是做什么用的」的抓手，也是 §1.5 新规则刚刚修好的东西（`computer_use_win` 从 id 变成 `Computer Use Win`）。
- 只写名字（152 B）省 128 B，但会让阶段 1 的 label 改进完全无法惠及提示词侧；只写 label 则丢掉工具名这个锚点。

实测：规则段 **615 B** + 名单 **280 B** = **895 B**（现状 **1341 B**，省 446 B）。

> **注意字节稳定性。** `state.noticeText` 的注释写得很清楚：「Built once: prompt-prefix text must not drift between turns」（`lib/index.js:670-681`）。名单行包含**家族数量**，而家族数量会随插件安装变化 —— 这是允许的（变化本来就该触发一次前缀重写），但**不能**在名单里放成员数、token 数这类每轮可能变的东西。构造时只允许读 `collapsed`（已冻结表面）与 `families`（家族表），并要求 `buildNotice` 保持纯函数。

### 2.5 `staticNotice = false` 时的兜底

`staticNotice` 关闭后，系统提示词里没有那段说明。此时网关 description 是模型唯一的信息来源，**必须自带最小可用说明**。设计：

```js
function describeGateway(family, options) {
  const label = family.label || family.id;
  const detail = family.description || "";
  const head = detail === "" ? `网关 · ${label}` : `网关 · ${label}：${detail}`;
  // `staticNotice` 关闭时，这句话是模型唯一的线索，所以它必须自解释；
  // 打开时系统提示词已经把同样的信息说了一遍，这里就不再重复。
  return options?.selfExplaining === true
    ? `${head}\n用 action="list" 查看成员，action="call" + tool + arguments 调用。`
    : head;
}
```

`createGateway` / `reconcileGateways` 已经把 `runtime` 传进来了，`runtime.config().staticNotice === false` 时置 `selfExplaining: true` 即可。实测兜底行 **56 B × 12 = 672 B**，`staticNotice = false` 的最坏情况仍比现状省 ~966 tok。

**开关联动是硬要求**：`staticNotice` 从 true 切到 false 会让**每一个**网关 description 变长 —— 也就是 wire 字节变化。这没问题（一次配置改动触发一次前缀重写），但要在 `syncGateways` 里把 `staticNotice` 纳入「网关是否需要重建」的判定，否则会出现「开关关了但网关描述还是旧的」。目前 `reconcileGateways`（`lib/gateways.js:148`）只按**名字**增删，所以这里必须补一个按 family 内容的比对。

### 2.6 参数 schema（可选，收益小）

`GATEWAY_PARAMETERS` 现状 `JSON.stringify` = **473 B/个 ×12 = 5676 B ≈ 1774 tok**。精简后：

```js
const GATEWAY_PARAMETERS = {
  action: { type: "string", required: true, enum: ["list", "call"],
    description: "list 取回该家族全部成员的定义；call 调用其中一个成员" },
  tool: { type: "string", description: "action=call 时的成员工具名（先 list）" },
  arguments: { type: "object", additionalProperties: true,
    description: "action=call 时传给成员的实参对象" },
};
```

`JSON.stringify` = **363 B/个 ×12 = 4356 B ≈ 1361 tok**，省 413 tok。

**但这一项优先级最低**：参数文案只有 3 个、不随家族数增长（参数 schema 数量恒为 3，是「×12」的家族数在放大它，而家族数由用户装了多少插件决定）。建议放在阶段 3，且**改之前先确认 `test/run.mjs:196-211` 的断言仍成立**——那组断言检查的是 schema 的**形状**（`required === ["action"]`、`action.enum === ["list","call"]`、`arguments.additionalProperties === true`、序列化后不含成员名），只改 `description` 文本不会破；改 `type`/`required`/`enum` 会破。

## 7. 风险与回滚

| 风险 | 影响 | 缓解 |
|---|---|---|
| `pluginPackages` 在 `apply()` 执行时还没就绪 | 一次读到空描述 | `ctx.get()` 软取 + `mtime` 缓存：下一次家族重建（任何插件变动、配置变动都会触发）自然补上。实测该服务在 profile entries 之前注册，正常时序下不存在这个窗口。 |
| 某插件 description 极长或含换行/控制字符 | 网关 description 变形 | `summarize` 先 `replace(/\s+/g, " ")` 压平，再按码点截断；控制字符一并被压平为空格。 |
| 描述的字节会随插件升级变化 | 一次提示前缀重写 | 这是正确行为（信息真的变了）。`state.noticeText` 已按 agent 缓存，不会因此每轮抖动；网关 description 只在 `reconcileGateways` 重建时才变。 |
| 过滤内置 ungrouped 后用户以为页面漏了 | 可发现性下降 | `ungroupedBuiltin` 计数 + 一行说明（§3.3）。 |
| `staticNotice` 与网关 description 脱钩 | 关掉 notice 后模型失去全部线索 | §2.5 的 `selfExplaining` 分支；并把 `staticNotice` 纳入网关重建判定。 |
| 归一化包名让某些家族成员归属改变 | 家族 id / 网关名变化 → wire 变化 | `barePackageName` 只影响**没有对应工具的 entry**（`dsh-ops/*` 子路径 entry 本身不注册工具，其工具归属仍在 `dsh-ops`）。需要回归确认 `describe` 里 12 个家族的 `packages` 与 `gateway` 完全不变。 |

**回滚**：本方案四个阶段互相独立。阶段 0/1 只加字段（`descriptionSource`、`metadata`），关掉只需让 `resolveNow` 不传 `metadata`；阶段 2 的回滚点是 `describeGateway` 与 `buildNotice` 两个纯函数；阶段 3 的回滚点是 `bridge.js` 的那一行 `continue`。**没有一处需要动注册表或数据迁移。**
